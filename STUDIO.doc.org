** The pipeline model

Every stage reads and writes files in a per-job =<input>.studio/= directory, so
each stage runs alone, resumes cheaply and never repeats fresh work.

| Stage      | Reads                     | Writes                    |
|------------+---------------------------+---------------------------|
| extract    | the media file            | =audio.wav= (16 kHz mono) |
| transcribe | =audio.wav=               | =transcript.json=         |
| diarize    | audio + transcript        | =transcript.json=         |
| translate  | =transcript.json=         | =transcript.<track>.json= |
| style      | transcript + styles.toml  | =subs.<track>.ass=        |
| render     | media + =subs.<track>.ass= | =render.<track>.mp4=     |
| mux        | media + every =subs.*.ass= | =subtitled.mkv=          |

=transcript.json= is the single contract: segments with start, end, text,
per-word timestamps, per-segment language and speaker, plus a speakers map
whose =SPEAKER_XX= ids are stable forever, renaming only fills a display name.
=state.json= records each stage's input hashes, =run= skips stages whose inputs
did not change and =--force STAGE= invalidates from a stage onward.

A video carries as many subtitles as you want: one =transcript.<lang>.json= per
language, each with its own =subs.<lang>.ass=. The last two stages are the two
ways of delivering them — =render= burns ONE language into the picture, =mux=
puts EVERY built language into one Matroska file as switchable streams, copied
rather than re-encoded so it costs seconds and no quality.

* USAGE

** The three front ends

One set of stage functions, three ways to reach them, so the way of working
never changes the result.

| Front end | Command | Suits |
|-----------+---------+-------|
| CLI | =subtitle-studio <stage> INPUT= | scripting, one-off runs, remote shells |
| TUI | =subtitle-studio ui [INPUT]= | a terminal session, keyboard-only work |
| Web | =subtitle-studio web [INPUT]= | many languages at once, a big preview, side-by-side panels |

The web studio is a Vue 3 page built into =web/dist= and served by a standard
library HTTP server inside the package. It is a GUIDED FLOW: a spine across the
top states the three steps the tool is made of — SOURCE (once per video),
SUBTITLES (once per language), DELIVER (last) — each with its state in one word,
its situation in one sentence and the one action that moves it forward. The
workspace shows the active step beside a preview that never moves; a status bar
carries the running stage, its progress and the files produced, with the log
opening on request. Controls follow the nano-core dashboard grammar — one widget
shape, titled bands, help in =?= tooltips — and ONE state vocabulary is used
everywhere: ready · out of date · not made yet · working. It binds to localhost, answers only
localhost, runs one stage at a time like every other front end, and streams
stage progress to the page over server-sent events. The page never talks to
anything but this server.


** Inputs

Any local video or audio file ffmpeg can read. No URLs, no uploads.

** The three language modes

| Mode     | Ask                    | Subtitle track                          |
|----------+------------------------+-----------------------------------------|
| verbatim | style with no translate | matches the spoken language everywhere |
| unify    | =translate --to LANG=  | one language, native parts untouched    |
| swap     | =translate --swap=     | each part shown in the other language   |

Every segment carries its own detected language, so a bilingual video unifies
by translating only the foreign parts (word timing survives on the untouched
ones) and swaps by crossing exactly two detected languages.

** Styling

All looks live in ONE central =styles.toml= at the project root: base
=[default]=, named =[style.NAME]= presets and =[speaker.KEY]= overrides,
resolved in that order and referenced by name (=--preset=, TUI dropdown, the
=styles= command lists them). A =styles.toml= next to a video overrides the
central file for that video only. Position is a live choice at style time
(=--position= or the TUI dropdown), never config. Rounded backgrounds and glow
are drawn by the tool itself, sized from the real font's glyph metrics, so they
fit the text exactly.
